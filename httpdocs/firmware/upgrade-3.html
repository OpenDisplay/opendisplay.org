Upgrading to Firmware 3

What changes

Firmware 3 drives the e-paper panel from the device's configuration: the panel's init sequence, waveforms and colour codes are packets in the config (how panels are described). A configuration made for 2.x does not have them, so after the upgrade the Toolbox adds them for your panel. It shows you what it will add and asks first; it changes nothing else.

  • Firmware 3 comes from OpenDisplay/Firmware_Unified. Firmware 2.x from OpenDisplay/Firmware stays available in the Toolbox.
  • In the Toolbox's version list, firmware 3 is marked firmware 3, config-driven. It is not installed unless you pick it.
  • Some panels are not available on firmware 3 yet. The Toolbox shows them as not yet on 3.x with the reason; keep those displays on 2.x. Panels converted from the 2.x driver but not yet seen working on a real panel are marked untested on glass.

ESP32 (S3, C3, C6, classic)

The settings are erased

2.x keeps its settings in a file system that 3.x does not read, and some boards change their partition table. Installing 3.x starts the board without settings, including its encryption key.

  1. Connect to the display in the Toolbox and choose Update the firmware.
  2. Pick the firmware 3 version, then Connect and save the settings. A file is downloaded; it contains the encryption key, so keep it private.
  3. Install over USB.
  4. Press Connect and restore the settings. The Toolbox writes the saved settings back, adds the drive data for your panel, reads the configuration back and checks it.
  5. Send an image and look at the panel.

Later 3.x updates keep the settings: they do not write the settings area of the flash. esp32-s3-N4R2 and esp32-wrover-e-N4R8 boards have no 3.x build yet and stay on 2.x.

nRF52840 (Seeed EN04, XIAO nRF52840, OpenDisplay kits)

The settings are erased, and the first install is over USB

3.x stores its settings differently from 2.x. It also uses a different bootloader layout (MCUboot) so that later updates can be made over Bluetooth; moving to it is a one-time USB install. The images are signed with MCUboot's published development key.

  1. Save the settings as for ESP32 (Toolbox, Update the firmware, firmware 3, Connect and save the settings).
  2. Install over USB. The EN04 has no USB drive; the Toolbox uses serial DFU.
  3. Restore the settings with Connect and restore the settings and look at the panel.

Later 3.x updates can be made over Bluetooth with the OTA image from the release (nRF Connect Device Manager or Home Assistant).

Provisional: how the one-time MCUboot install is packaged for the browser (a serial-DFU package or a USB-drive image) is decided with the 3.0 release files. Until the Toolbox offers firmware 3 for your board, use the release notes of Firmware_Unified.

EFR32BG22 (M3 Pro, M3 Core)

The settings are kept across the update: 3.x reads the same storage. The panel stays blank after the update until the drive data is written, so do the steps in this order:

  1. Optional: save the settings to a file (Toolbox, connect, Save the settings to a file).
  2. Install the 3.x .gbl over Bluetooth (Home Assistant or Simplicity Connect; the website does not install BG22 firmware).
  3. Connect in the Toolbox. It sees a 3.x device without drive data and offers to add it. Confirm.
  4. Send an image and look at the panel.

BG22 stores at most 3120 bytes of configuration on 3.x (2048 on 2.x). The Toolbox refuses to write a larger one and says by how much it is over.

nRF54L15 / nRF54LM20A (XIAO)

Install the 3.x image over USB from the Toolbox, then set the display up again or restore saved settings. Drive data is added as for the other boards.

nRF52811 boards (M3 with Firmware_NRF)

These cannot be updated to firmware 3. They keep working with the Toolbox as they are.

If something goes wrong

  • The panel stays blank on 3.x: connect in the Toolbox. If it offers to add drive data, confirm. If it says the panel is not available on 3.x yet, install 2.x again and restore your settings file.
  • Yellow and red are swapped: the panel's colour code map is wrong in the panel database. Report it with the panel's part number.
  • Restoring fails with a size error: remove something you do not need (Wi-Fi, Find My, an extra drive mode) in the Toolbox editor and write again.
